## Native shadow spatial playback

Original min/max distance fields +320/+324 are independently confirmed by the USA setter 82795C40 (called via 82787BF0 at 82839814), and getter 82791E20. The shadow observer now supplies these values, sound mode and listener/source position to X3DAudio during start and subsequent parameter updates. Old FMOD Ex mode bits and handedness are cross-referenced against the 4.24.16 header; the native model uses linear or unit-factor inverse-distance attenuation and rejects custom curves. X3DAudio is used for directional coefficients with a unity volume curve when the native approximation supplies distance gain, avoiding double attenuation of the 3D leg. FEV Pan3DLevel blends the flat and spatial matrices. DSP-backed voices can update coordinates/pan/3D blend without restarting or refiltering PCM. The real original mixer is still authoritative and the shadow remains muted. This is not a bit-exact FMOD mixer or full ABI replacement; custom curves, exact global rolloff, cones, occlusion, Doppler, original stereo emitter law, multiple listeners and the Windows build/game test are not verified. The spatial math and synthetic memory capture test passed locally with GCC and Clang C++20; Windows-specific code has not been compiled.

## Native Doppler, inherited pause and live DSP-backed gain/pitch

The muted shadow now computes a bounded native Doppler factor from already-observed source/listener velocity and position. The explicit experimental assumption is 343.5 world units/second and unit Doppler scale, not a verified FMOD world-unit conversion or exact original acoustic kernel. The FEV 3D pan level blends the Doppler factor with unity; host pitch composes base, automation and Doppler once and bounds only the spatial contribution to the supported voice range. Pitch is reapplied when spatial state changes, when an FEV block changes and when a source is replaced on seek. The legacy default spatial factor remains unity. The original channel pause ABI is confirmed at 82790A38 and 82790B48: channel+116 bit 0, group+89 pause byte and ancestor pointer +28. Capture preserves unknown state on malformed memory; shadow voices are admitted paused when observed and then updated in place. Single-snapshot DSP-backed voices now update gain/pitch without replacing their pre-rendered buffer or multiplying the automation twice. Their named DSP coefficients are still baked at admission; live filter updates, exact FMOD Doppler factors, acoustic effects and full ABI takeover are not claimed. The new portable Doppler, inherited-pause and spatial capture regressions passed on GCC and Clang. Windows-specific integration has not been compiled or exercised; original audio remains authoritative.

## Live named DSP streaming

Single-snapshot shadow FEV voices now use the existing reconstructed stateful scalar DSP algorithms on a bounded three-slot PCM stream. The original immutable decoded waveform remains resident. Each released 1024-frame buffer is refilled in the XAudio2 callback, with no allocation or game mutex in that callback. The game audio update resolves original named effect parameters and publishes a complete chain through atomic words; the reader retains its prior chain if a publication is in progress. Filter histories are preserved across blocks according to the existing scalar algorithm. Gain, pitch, pan, pause and spatial changes reuse the same voice. Existing finite pre-rendered schedules remain unchanged. Dynamic seek/looping with live DSP is explicitly unsupported; changing a time-offset control rejects the affected shadow voice instead of silently losing synchronization. The portable stream and concurrent publication test passed under GCC and Clang C++20 (including reference agreement with the existing offline scheduler). The Windows callback and realtime performance remain untested. This is not an exact original DSP graph, acoustic model or complete FMOD ABI replacement; original playback is retained.

## Native wet reverb fallback

The Windows mixer now has an opt-in parallel mono XAudio2 submix with the native reverb APO and an explicit generic I3DL2 preset, configured 100% wet. Original observed per-zone sends are summed and capped at unity, with duplicate owner, invalid values and malformed count rejected. Mono is sent directly and stereo averaged to mono. The dry spatial matrix remains separate from the wet send. Source seeks preserve the send on their replacement voice, and voice pause and retirement keep the existing lifecycle semantics. The effect is lazy and failure to initialize rejects the opted-in shadow voice without affecting the original audio. Source and wet submix volumes honor shadow mute. Current valid spatial snapshots update the wet coefficient without restarting the voice; missing send capture retains the last observed value. This is an approximate single-room native effect, not the original FMOD reverb DSP: individual room properties, multiple simultaneous room processors, original reverb tail and geometry behavior, full FMOD ABI replacement and Windows runtime execution are not verified. The portable send and mono/stereo matrix tests passed on GCC and Clang with -Wall -Wextra -Werror. The Windows-specific path was reviewed against Microsoft xaudio2fx.h documentation but has not been compiled. Original audio remains authoritative.

## Native FMOD Ex compatibility direction (owner decision)

Keep original FEV/FSB and original sound behavior. The target is elimination
of the console audio execution dependency, not removal of the FMOD product.
Native Windows x64 FMOD Ex is a legitimate option; Studio's API is not a
drop-in legacy Event API. The installed native XAudio2 shadow code remains
as a fallback; this change neither disables original playback nor enables
another audible game mixer.

An explicit local-only compatibility executable now builds from the owner's
matching legacy FMOD Ex SDK headers (no proprietary SDK files checked in).
Example from the repository root on a Windows x64 Visual Studio shell:

    cmake -S native_port -B build-fmod -A x64 -DHULK_NATIVE_CORE_ONLY=ON -DHULK_FMOD_EX_SDK_INCLUDE_DIR="C:/FMOD-Ex/api/inc"
    cmake --build build-fmod --config Release --target hulk_fmod_ex_probe
    build-fmod/Release/hulk_fmod_ex_probe.exe "C:/FMOD-Ex/api/bin"

Pass optional original PC-format FEV path, FSB media directory and full
event name to exercise real event load/start/update/stop. Use a legitimately
obtained matching x64 pair fmodex64.dll/fmodevent64.dll in the explicit
directory. No search of the working directory, no DLL download, no use of
the 32-bit retail PC DLL in a 64-bit process, and no modification of game
archives. SDK signatures are used directly through dynamically bound C
exports, and both core and event runtime versions must equal their matching
header versions before initialization. A successfully observed playing state
does not prove every event, audible output, or guest ABI coverage. Test PC
banks first; compatibility with the exact USA Xbox banks is separate and
must not be assumed. The standalone executable does not yet replace in-game
event routing. No Windows SDK/DLL pair was found in the accessible inputs in
this pass; compilation and native playback have not been performed.

Reference legacy C API declarations: https://github.com/thibaudcolas/icopter/blob/master/Classes/engine/sound/FMOD%20Libraries/Headers/fmod_event.h

## Independent native room sends

XAudio2 remains the primary implementation direction. The live shadow now routes each validated positive original FMOD reverb send to a separate XAudio2 reverb submix keyed by source room owner. The existing single-room API remains available but is no longer selected by the live shadow. The bounded route planner preserves independent gains (no summing or clipping them to unity), canonicalizes owner order, rejects duplicates, missing nonzero room properties and overflow (8 sends per voice). Up to 32 room processors are retained; an unreferenced slot can be recycled after a conservative 25-second tail allowance when capacity is reached. Active, paused and pending sources retain ownership. All sends use the master input sample rate, and dynamic output graph changes restore the dry matrix after SetOutputVoices, per Microsoft documentation. Shadow mute and explicit stop-all apply to room processors. Missing room evidence retains existing routes during updates; a host routing error retires the affected shadow. The portable planner test was compiled and run on GCC and Clang C++20 with -Wall -Wextra -Werror. The Windows XAudio2 integration is not compiled or exercised, still muted, uses I3DL2 approximation rather than FMOD's exact acoustic response, and does not establish independent event/ABI execution. Reference: https://learn.microsoft.com/en-us/windows/win32/api/xaudio2/nf-xaudio2-ixaudio2voice-setoutputvoices

Room lifecycle follow-up: refresh the tail timestamp immediately before a source is pruned, explicitly stopped or disconnected from a zone, not only on spatial observations. Skip redundant wet matrix calls when owner topology and gain are unchanged. This is Windows source review; not an executed host audio test.
